## 重点验证的机制

1. **v0.10 方案预览先行**：先产出 preview.md（Mermaid 10 边，自检通过）再展开 spec/code；用户豁免确认等待后流程不停顿，预览仍作为骨架保留。
2. **v0.9 git notes**：评审摘要真实写入 `refs/notes/review` 挂在被评审提交，验证：不改哈希、不进代码树、list/show 可读、独立 ref。
3. v0.8 受阻机制未触发（全程零返工，23 测试一次通过——同栈复用让流程很顺）。

## 发现的 skill 优化点（回灌 v0.11）

1. **「跳过确认」缺正式定义**：用户说不用问时，之前只能临时 journal。v0.11 在铁律 1 明确这是「本次任务确认门禁的一次性豁免」——产物仍出、按推荐推进、记 journal、不延续到下一 change。
2. **notes 持久性易被忽略**：notes 不随普通 clone/push 走，新机器不 fetch 就看不到。v0.11 在 review.md 加备份/恢复说明（fetch 命令 + 提醒 change 下 review.md 才是随代码走的唯一存档）+ 归档提交不自动继承备注。
3. **预览对同栈增量收益递减**：本次复用 v1 架构，完整 Mermaid/分层图价值低。v0.11 允许同栈增量时预览精简为「差异 + 特有取舍」，但要求先读代码确认真同栈。

## 设计轴产出（SUGGESTION）

判重用「先 count 再 insert」两段式，高并发有 TOCTOU 窗口（唯一索引已兜底）；多实例时可下沉为直接 insert + 约束异常映射。单实例内网现状可接受，挂账不阻断——验证了设计轴「提真建议但不凑数、YAGNI」的定位。
