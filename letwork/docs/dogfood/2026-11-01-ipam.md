# 狗粮测试 #5：用 letwork 开发 IPAM 管理系统（首个分层业务系统）

- 日期：2026-11-01
- 被测 skill：letwork v0.6
- 测试项目：/Users/admin/work/ipam（Spring Boot 3.4 + JdbcTemplate + H2/MySQL，JDK 21），change `add-ipam-core`，18 次提交，38 个测试
- 目标：首次覆盖真实分层业务系统，检验阿里规范**数据库分册**（J-DDL/J-IDX/J-SQL/J-ORM）与 v0.6 的绿色分批提交。

## 产出

- 两个 capability：子网管理（CIDR 校验/重叠检测/容量/删除约束）、IP 分配（自动顺序/手动指定/冲突耗尽/回收复用）。
- 分层：domain（纯 JDK Cidr 值对象）/ model / dao（全参数化 SQL）/ service（业务规则与 400/404/409）/ web（REST + 统一错误体）。
- H2 测试库 + MySQL 8 生产 DDL；38 测试（领域单测/DAO 集成/Service/WebMvcTest 切片/启动冒烟）。
- 真实 HTTP 九连冒烟全符合 spec；jsecscan 交叉扫描 19 个生产文件 0 命中。

## 首次覆盖的规范与机制

| 项 | 结果 |
|---|---|
| J-DDL（utf8mb4/全列 COMMENT/审计列/表注释） | ✅ MySQL DDL 全部落实 |
| J-IDX（cidr/name 唯一、(subnet_id,ip_num) 唯一、subnet_id 普通索引） | ✅ |
| J-SQL/J-ORM 全参数化 | ✅ DAO 全部 `?` 占位，jsecscan J-SQL 0 命中 |
| J-LAYER 分层单向依赖 | ✅ web 不碰 dao |
| v0.6 绿色分批提交 | ✅ 14 个业务提交按任务与 feat/test 分离，每个提交点 mvn test 为绿 |

## 被测试拦截、未进入提交的缺陷（2 个）

1. `RETURN_GENERATED_KEYS` 在 H2 下把 `DEFAULT CURRENT_TIMESTAMP` 列也算作 generated keys，getKey() 报错 → 改为 `prepareStatement(sql, new String[]{"id"})`。
2. WebMvcTest 误用 Mockito 的 `contains()` 当 Hamcrest 匹配器 → 改 `containsString`。

两者都在「局部快反馈」阶段发现，提交历史保持全绿——验证了 v0.6 绿色提交不变量的价值。
