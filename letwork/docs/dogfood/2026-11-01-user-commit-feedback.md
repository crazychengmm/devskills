# 实测反馈 #4：commit 阶段不会做、无法选择性分批提交

- 日期：2026-11-01
- 来源：用户在真实使用中直接反馈（非完整项目狗粮）
- 现象：小任务完成、功能测试通过后，skill 不会主动提交；缺少「选择性、分批、且每批不破坏工程编译执行」的机制。

## 暴露的问题

1. commit 阶段太被动：规程是「停下提示用户选择」，用户感受是「它不会提交」。
2. 没有明确的**绿色提交不变量**：每个 commit 独立 checkout 都应可编译可测；半成品只能留在工作树。
3. 缺选择性暂存的操作路径：同文件混多任务时如何只提交部分 hunk（`git add -p` / `git apply --cached`）。
4. 工作树有半成品时，普通全量测试无法保证「commit 本身」是绿的。

## 回灌内容（v0.6.0，commit.md 重写）

- **主动提交**：任务测试为绿后主动给出分批方案，用户确认即执行。
- **绿色提交第二铁律**：任何 commit checkout 出来都必须编译/测试通过；实现先于测试分提。
- **选择性暂存**：文件级 + hunk 级（交互 `git add -p` 或非交互 patch apply --cached）。
- **分批顺序**：基础设施 → 实现 → 接线 → 测试 → 文档，按依赖序逐批。
- **严格模式**：`git stash push --keep-index` 只验证暂存快照，命令在 scratch 仓库实测通过后写入规程。
- SKILL.md 铁律 3 与阶段表同步更新；code.md 交接语改为「test 通过后主动准备提交」。

## 验证

- scratch 仓库实测：工作树同时含完整任务 A 与无关半成品 B 时，只暂存 A 的文件 → stash --keep-index → 测试绿 → 提交 → pop，历史中该 commit 独立可测，B 保留在工作树。
