# 实测反馈 #16：事项清单/不变原则/设计优先（v0.19）

- 日期：2026-11-19
- 来源：用户三点优化要求

## 1. 多事项清单 + 主动小版本提交（铁律 0 + commit.md）

- 一次交代多件事：先出编号事项清单（开发类映射 tasks.md，杂项对话显式列状态），逐项闭环、完成即汇报，不混做。
- 大改动/多事项时，每个可独立编译测试的里程碑主动提示**本地**小版本提交（用户同意才做）；push 仍两级确认。

## 2. 项目不变原则文件（templates/principles.md）

- 新增 `openspec/letwork/principles.md`：项目级、跨 change、归档不重置，只放稳定价值观/硬约束（输入校验、参数化 SQL、提交必须绿色等）。
- 与 ADR 区分：原则回答「永远如何」，ADR 回答「这次选了什么、否了什么」；与 glossary 区分：原则是规则，术语表是词汇。
- skill 只读不覆盖，修改权在用户；review 发现代码违反原则必须报 BLOCKER/MAJOR。

## 3. 设计优先（references/design-alignment.md）

- 触发：涉及算法（限流/缓存/重试/解析…）或设计模式（多实现分发、创建族、发布订阅、状态机…）。
- 流程：列 2–3 候选（问题/结构/代价）→ 推荐 → 用户确认 → 落 ADR → 才写实现。
- 内置「问题信号 → 模式/算法」速查表（策略/工厂/模板方法/观察者/状态机/令牌桶/LRU 等，含不适用场景，防止过度设计）。
- 编码顺序：抽象骨架（接口/模型/签名，编译通过）→ 参考实现打通主链路 → 同构实现 + 重复逻辑抽基类 → 边界异常。
- review 轴三检查实现是否偏离 ADR，偏离必须新建 ADR。
