# intake — 既存项目摸底（首次 coding 前）

**触发条件**：进入一个在我们介入前就有业务代码的仓库（git 历史里有代码提交、已有 src/包结构）。全新空仓库跳过本阶段（说明「新项目，跳过摸底」即可直接走 analyze）。

目的：先看懂项目再动手，避免用自己的习惯覆盖既有约定；既存问题显式登记、由用户决定修与不修，而不是假装没看见。

## 1. 只读调查（先事实后判断，控制深度）

不要一上来通读全部代码，按以下顺序快速建立全貌（单项目调查控制在 ~20 个文件以内）：

1. **构建与依赖**：pom.xml/build.gradle/go.mod/requirements.txt/pyproject.toml/package.json——语言、框架、构建/测试命令、过时或冲突依赖。
2. **模块结构**：目录树限定 2–3 层；每个包/模块读 1–2 个代表性文件归纳职责，记录到模块表（猜测要标注，不臆断）。
3. **代码风格**：命名约定（包名/类名/缩写习惯）、分层方式（controller/service/dao 或其他）、异常处理与日志风格、注释密度；查格式化/静态检查配置（.editorconfig、spotless/checkstyle、ruff、gofmt）。
4. **测试现状**：框架、测试目录结构、能否一次跑通（记录基线结果与耗时），明显缺测的核心模块。
5. **跑一次机械检查基线**：编译 + 测试 + lint（p3c/ruff/gofmt/vet），记录违规量级，不当作本 change 的债。
6. **搜问题信号**：TODO/FIXME/XXX、注释掉的代码块、空 catch/printStackTrace、明显重复实现、循环 import、死代码、硬编码环境地址。

## 2. 产出架构画像 `openspec/letwork/project-profile.md`

用 [模板](../templates/project-profile.md)，包含：

- 一句话定位 + 技术栈与运行方式；
- **Mermaid 分层/依赖图**（模块及调用方向，第三方中间件标注）；
- 模块职责表；
- 观察到的代码约定（与冻结规范 checklist 有差异时逐条列出，决定「跟随项目既有风格」还是「按规范整改」——既有项目默认入乡随俗，只有安全类强制规则例外）；
- 构建/测试/检查命令（后续阶段直接复用，不再重新摸索）。

画像先给用户确认（符合 v0.10 预览先行：画像本身就是方案预览的一部分）。

## 3. 既存问题台账 `openspec/letwork/debt-backlog.md`

用 [模板](../templates/debt-backlog.md)。每条技术债：

- 编号 `DEBT-001`、位置（文件:行/模块）、现象、风险、建议处理方式、关联模块关键词（用于后续匹配）；
- 状态：`OPEN-待用户决定` / `DEFERRED-暂缓` / `FIXING-随某change处理` / `CLOSED`；
- **逐条征询用户**：现在修 / 暂缓。暂缓的记录决定与日期；用户明确不改的保留 OPEN→DEFERRED，不偷偷改。
- 顺手能修的小问题（如明显笔误、死 import）可并入首个 change，但必须在该 change 的 proposal 影响面中列明。

## 4. 与后续流程联动（关键：欠债要在相关模块被触碰时复现）

- **analyze 新 change 时**：读取 debt-backlog，按「关联模块关键词/文件路径」匹配本次需求涉及的模块，把匹配中的 DEFERRED/OPEN 条目列出来，再次询问是否本次一起修；用户仍选择不改则更新「上次回顾日期」，不反复纠缠同一条（同一 change 内只问一次）。
- **code/review 时**：review 第零轴额外检查本次 diff 是否触及 backlog 条目关联文件；触及且用户决定本次修的，验证修复；决定继续暂缓的，在 review 报告 INFO 区注明「已知欠债，见 DEBT-xxx」。
- **修复闭环**：条目随某 change 修掉后，在 backlog 标 CLOSED + change 名与提交 SHA，journal 记 `[NOTE] DEBT-xxx 已关闭`。
- 新发现的既存问题（非本次引入）随时追加进台账，走同样的确认流程，不要直接混进当前任务的提交。

## 5. 边界

- 摸底不是重构许可：没有用户确认，只读调查 + 文档产出，不动业务代码。
- 画像与台账是**项目级长期文档**（在 `openspec/letwork/` 下，不属于某个 change，随仓库提交）；多次进场只需增量更新。
- 小项目（<10 个源文件）允许一页简版画像 + 口头问题清单，但台账文件仍要建立。
