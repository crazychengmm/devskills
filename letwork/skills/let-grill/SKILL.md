# let-grill — 通用拷问入口

一场**纯 grilling 访谈**，零前置依赖：不需要 git、不需要 OpenSpec、不写 proposal/spec、不预设是软件需求。商业决策、技术选型、旅行计划、采购、合同、组织方案——任何「还没想清楚的事」都适用。

## 与 /let-analyze 的区别

| | /let-grill | /let-analyze |
|---|---|---|
| 前置 | 无 | git 仓库 + OpenSpec change |
| 适用对象 | 任何想法/决策 | 软件需求 |
| 产出 | 结论 +（可选）ADR/术语表/问卷 | proposal/design/spec/tasks |
| 提问方法 | grilling（见下） | grilling（同一方法） |

需要直接产出软件方案文档时用 /let-analyze；只想把一件事拷问清楚、或拷问非软件事务时用本命令。

## 方法：设计树访谈

1. 把问题建模成一棵**设计树**：每个决策分叉出依赖它的子决策。
2. **frontier** = 前置条件都已确定、现在就能问的决策集合。一轮问完整张 frontier，编号 Q1..Qn。
3. 每个问题给标题、选项（可多选）和 `➡️` 推荐答案，措辞让用户回「yes」即可采纳。
4. **事实自己查，决策才问人**：能搜索/读材料确认的不问用户；只问取舍、偏好、约束。
5. 用户回答后重算 frontier 进入下一轮；frontier 清空且用户确认想清楚了才结束。

轮次格式：

```
❓ **Q1 - <标题>**：<问题正文，可给选项>
➡️ <推荐答案及理由>
```

覆盖清单（按需取用，非软件事务映射理解）：真实目标与成功标准、约束（预算/时间/权限）、可选方案与被否方案、最坏情况与不可逆点、相关方及其诉求、衡量「选对了」的指标。

## 三种可选沉淀（访谈中实时，不要事后补）

用户需要可产出文档；软件项目里这些文件也可被后续 /let-analyze 直接复用：

1. **术语表**：访谈中出现的关键名词当场对齐，避免同物异名。模板见 [templates/glossary.md](../../skills/letwork/templates/glossary.md)。
2. **ADR（架构/决策记录）**：关键取舍一旦拍板立即记录（背景/决定/理由/被否方案/后果），而不是等全部收敛后回忆。模板见 [templates/adr.md](../../skills/letwork/templates/adr.md)。
3. **异步问卷**：遇到「需要问没在场的人（运维/甲方/家人/老板）」的决策时，按**两步法**——先拷问清楚「发给谁、要拿回什么」（任一答不上来就不发），再动笔写；问题一题只含一个概念（禁止复合题），按 P0/P1/P2 排序，每题给选项与推荐默认，并明确允许对方答「不知道，按推荐来」。模板见 [templates/questionnaire.md](../../skills/letwork/templates/questionnaire.md)。

## 结束

输出一段结论：已确定的关键决策（链接到 ADR 编号）、统一术语、**仍挂起的信息差**（问卷清单及阻塞了哪些决策）。明确告诉用户：哪些可以现在行动、哪些要等问卷回收。
